# Atualizacao 004 - API financeira

Data: 22/10/2026.

## Mudancas

Contratos estritos, normalizacao de UUID, Money com escala fixa na borda, SHA-256 de JSON canonico recursivo com chaves ordenadas e apenas campos de negocio. Header Idempotency-Key obrigatorio e separado do hash.

WageringPort e ProviderIdentityPort, caso de uso reutilizado por HTTP/SQS, endpoints de wallets/transacoes/ledger/reconciliacao, cursor opaco vinculado a wallet, health separado e mapeamento de erros por categoria.

## Revisao

1. src/application/contracts.ts: validacao e hash.
2. src/application/wagering.ts: fluxo independente de NestJS.
3. src/interfaces/http/api.ts: contratos e codigos HTTP.
4. src/infrastructure/persistence/queries.ts: paginacao e reconciliacao sob lock.
5. tests/integration/http.test.ts: ciclo HTTP com PostgreSQL real, replay, conflito, rejeicao, referencia pendente e readiness.

## Decisoes

BRL na borda, dominio com moedas distintas testadas. LIMIT 1..100. Dinheiro admite ate 28 digitos inteiros, dentro de NUMERIC(30,2); overflow do saldo por credito ainda depende de erro do PostgreSQL e sera revisado no Dia 3. Auth externa adiada com ponto de extensao explicito. Health aberto.

Ajuste de schema: somente transacoes PROCESSED precisam ter moeda igual a da wallet, permitindo rejeicao auditavel de payload em moeda conflitante; ledger continua protegido por FK composta.
